## 一、《YouTube 短剧出海情报》日报（优先级最高，1-2 周）

### 目标
把"内部面板的今日简报"变成"可对外发送的每日情报"，作为获客钩子。

### 内容结构（Markdown，Telegram/飞书双通道）

```
📊 YouTube 短剧出海情报 · 2026-09-02
━━━━━━━━━━━━━━━━━━━

🔥 今日爆款预警 Top5（24h增量）
1. 🚀 [标题] — 频道 | +12.3万/24h | 总 45万
2. ⚡ ...

📈 24h 增量热榜 Top10
（表格：排名 | 标题 | 频道 | 语种 | 增量 | 总播放）

🌊 蓝海速报（本周）
• 题材「复仇×土耳其」动量 +40% 但供给仅 3 频道 → 蓝海
• 题材「霸总×英文」动量 +12% 但供给 243 频道 → 红海拼执行

✅ 本周验证的一条蒸馏规则
"钩子出现时间中位 95s 的频道，24h增量中位比全库高 2.1 倍"
（来源：字幕实证 + 增量数据交叉验证）

📊 自有频道健康度（内部版才显示）
━━━━━━━━━━━━━━━━━━━
👉 深度版（付费）：分语种全文 · 蓝海雷达图 · 诊断处方 · 历史趋势
```

### 数据流（零新增采集）

```
alerts_latest.json ─┐
knowledge_graph.json ─┤→ build_daily_report.py → 日报.md → Telegram/飞书
p0_report.json ──────┤
distill规则(Top1) ───┘
```

### 实现

1. `scripts/build_daily_report.py` — 读三处数据 → 生成 Markdown
2. 蓝海速报：读 `knowledge_graph.json` 的 `genre_rank`，动量增速 vs 频道供给做四象限速判（先出文案，雷达图后续）
3. cron 每日 09:00 生成 + 推 Telegram（复用现有通知链）
4. 前端：面板加"日报预览"页（可选，先发出去验证）

## 二、标题真相引擎（输入标题 → 看穿它）（2-4 周，随字幕放量增强）

### 目标
输入任意标题（竞品新视频 / 自家备选标题），输出：真实题材预测 + 标题通胀风险 + 同类内容历史表现。

### 核心（复用一个关键洞察）
L0（标题）× L1（字幕内容）混淆矩阵 = **标题通胀系数**。
- L0：标题关键词 → 预测题材（distill 的 extract_content_tags + genre_vocab）
- L1：字幕内容 → 真实题材（字幕分析，带证据回查）
- 通胀系数 = P(标题说X | 内容实为Y)，即"标题承诺兑现率"

### 输入输出

```
输入: 任意标题（如 "CEO's Secret Baby"）
输出:
  1. 题材预测: 霸总 78% / 萌宝 45% / 甜宠 40%（标题层，来自 distill 词表）
  2. 通胀风险: 「CEO」标签在库内 243 频道中 92% 兑现为霸总内容（低通胀）
              「萌宝」标签 40% 视频标题提萌宝但字幕内容无萌宝（高通胀，警告）
  3. 同类表现: 库内 143 条「霸总+萌宝」视频，中位 24h 增量 8.2k，爆款率 12%
```

### 数据流

```
标题 ─→ extract_content_tags (distill) ─→ L0 题材分布
     ─→ genre_vocab (标题层匹配) ─→ 通胀矩阵查询
字幕分析(4318条) ─→ L1 真实题材 → 混淆矩阵 → 通胀系数
同类视频 ─→ 24h增量/播放/爆款率 统计
```

### 实现

1. `scripts/title_truth.py` — 输入标题 → 输出上述 JSON
2. 混淆矩阵：现有 `l1_calibration/confusion_matrix.py` 已有原型，接入 4318 条后增强
3. 面板加 API `/api/title-truth?q=...` + 前端页（可选，先 CLI 验证）
4. **内部第一用例**：校准自家 `generate_title.py` 的标题生成（生成前先查通胀风险）

## 三、蓝海雷达（语种 × 题材 × 钩子 四象限）（4-6 周，最后做）

### 目标
一张图回答："哪个题材在哪个语种是蓝海（高动量+低供给）、怎么做（钩子配置）"。

### 四象限（核心可视化）

```
          动量增速（需求）
              ↑
    蓝海 ●    │   热战 ●
  (高动量+低供给)  (高动量+高供给)
  「进场」      │  「拼执行」
              │
 ─────────────┼─────────────→ 频道供给（供给）
              │
    荒漠 ●    │   红海 ●
  (低动量+低供给)  (低动量+高供给)
  「观察」      │  「规避」
```

### 数据映射（全部现成）

| 轴 | 数据源 | 计算 |
|---|---|---|
| 供给 | `knowledge_graph.json matrix.cells` | 该 (题材×语种) 组合的频道数 |
| 动量 | `genre_rank.momentum_avg` 或 24h增量 | 需求增速代理 |
| 钩子配置 | `subtitle_analysis/p0_report.json` | 该组合 top 钩子类型 + 出现秒数 |

### 实现

1. `scripts/blue_ocean.py` — 合并三处数据 → 四象限 JSON
2. 面板新页 `BlueOcean.vue` — 散点图（ECharts）+ 点击题材 → 钩子配置 + 证据视频列表
3. 蓝海速报文本版先行（日报第3节），雷达图后续
4. 4318 条放量后，钩子配置列才有统计意义 → 所以排在最后

## 四、依赖关系与路线

```
周1-2  日报 build_daily_report.py（数据现成，代码复用度高）
         ↑ 同时做: cron IaC + 备份 + 告警（P1-6，日报承诺每日更新前必须）
周2-4  字幕放量 4318 → aggregate_v1 → p0_report 增强
         ↑ 标题真相引擎 title_truth.py（依赖放量后的混淆矩阵）
周4-6  蓝海雷达 blue_ocean.py + BlueOcean.vue（依赖放量后的钩子统计）
之后   搬运溯源 trace_v2（爆款匹配模式，另设计）
```

## 五、风险与验证

| 风险 | 缓解 |
|---|---|
| 日报承诺"每日更新"→ 采集断流被曝光 | P1-6 三件套必须先做（cron 入库 + 备份 + 告警） |
| 标题通胀系数在 189 条样本下不稳 | 放量 4318 后才有统计意义，先出"趋势方向"不出精确系数 |
| 蓝海雷达整合三套 schema | 数据合并层先出 JSON，面板渲染后置 |
| 日报泄露自有频道内部数据 | 对外版不含自有频道，内部版才显示（一个开关） |
