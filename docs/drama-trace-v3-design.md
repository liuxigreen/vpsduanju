# 搬运溯源 v3 设计（drama_trace_v3）

> 取代 trace_v2（猜剧名→验证）与 handoff §五的 v3 提案（写于 P0 188 条时期）。
> 本设计基于 **4497 条全量回传数据**（`data/subtitle_analysis/full_normalized.jsonl`，2026-09-03 落盘）。
> 用户流程：设计 → 本文档 git push → 评审确认 → 小样本测试 → 放量。

---

## 一、数据现状（设计的前提）

| 事实 | 数字 | 对设计的意义 |
|---|---|---|
| 全量回传完成，新 schema 齐 | 4497 条，synopsis/characters/distinctive_lines/evidence 全有 | handoff §五"先补字段再放量"的门禁**已满足**，指纹提取可直接开工 |
| 翻译剧占比 | 3908/4497 = 87% | 溯源是主战场，不是边角功能 |
| 繁中池 | 430 条，标题/角色名全中文 | **库内现成中文锚点**（v2/v3提案都没利用） |
| 角色名前缀重合 ≥3 次 | 377 个 | 跨语种姊妹聚类可行，实测过 |
| feels_translated 且非合集 | 292 条 | 单集切片，溯源质量最高的子集 |
| ⚠️ is_compilation=True | 4088/4497 = 91%，但时长大头在 30m–2h | **该标志已失真**（多集连剪全被标合集），选材逻辑不能依赖它 |

语种分布：英文 1396 / 印尼 936 / 葡 651 / 西 544 / 繁中 430 / 日 289 / 土 251。

## 二、核心思想（三个转变）

```
v2:  字幕 → LLM猜剧名 → 搜索引擎验证          ← 猜是黑箱，验证只是过滤噪声
提案: 字幕 → 指纹 → 搜索 → 打分 → 人工确认     ← 方向对，但没利用库内资产
v3:  先向内聚（库内指纹聚类，零成本），再向外搜（指纹搜索，有则加冕）
     溯源不是终点——输出回流成"搬运雷达"，和蓝海雷达/图谱闭环
```

1. **向内优先**：4497 条本身就是最大的证据库。一部剧被搬到 id/en/tr 三个语种，三个版本的角色名音译、台词直译、剧情结构会互相印证。先聚出姊妹簇，簇里有中文/繁中版本 → 母本几乎白送；全是外语 → 才值得花搜索配额。
2. **指纹而非猜测**：不再让 LLM 一步猜剧名。台词**直译**还原（不是意译）+ 角色名音译还原 + 非套路细节，三路指纹各自搜索、互相打分。允许输出 Top3 候选 + 证据链，机器不越权下结论。
3. **溯源即情报**：每条溯源结果落库后聚合成「中文母本 × 语种 × 播放表现」矩阵——"这部剧 id 版爆了、tr 版没人搬"就是蓝海信号，直接喂给蓝海雷达和图谱。

## 三、五层流水线

```
L0 触发
   ├─ 增量：爆款预警 + 24h热榜 中 feels_translated=true（日 10–20 条，搜狗红线内）
   └─ 存量：4497 条一次性批量（只跑 L1 库内聚类，零网络；L2–L4 只对预警级爆款跑）
        │
L1 库内指纹聚类（零成本，先跑）
   ├─ 角色名音译规范化前缀 + genre_l1 + synopsis 关键词 → 姊妹簇
   ├─ 簇内含 繁中/中文标题 条目 → 中文剧名候选直接提取（最强路径）
   └─ 纯外语簇 → 多语种指纹互相印证，生成更干净的还原输入
        │
L2 中文指纹提取（bai，模型走 model_router）
   ├─ a) 台词直译还原：distinctive_lines 逐句直译回中文 → 2–3 个中文短句
   │      （直译！"¿Cómo te atreves a pegarme? Soy tu prometido"→"你敢打我？我是你未婚夫"）
   ├─ b) 角色名还原：cn_surname.yaml 音译表 + bai → 中文人名候选
   └─ c) 独特细节：key_reveals/synopsis 里挑非套路词（套路词=霸总/复仇/打脸，搜了没用）
        │
L3 候选池搜索（强指纹→弱指纹，逐级降级）
   ├─ 1) 本地片单索引 cn_drama_index.jsonl（零请求，命中即强候选）
   ├─ 2) 搜狗微信 type=2 文章搜索（≥8s，只取标题+摘要文本，链接丢弃）
   ├─ 3) 百度（每次新建 Session + ≥8s + r.encoding='utf-8'）/ DDG 兜底（≥3s）
   └─ query 构造：人名+题材 / 直译台词加引号 / 独特道具词，禁止用搬运号标题搜（教训1）
        │
L4 打分 + 证据链 + 人工确认
   ├─ 候选剧 × 三路指纹 → 匹配度分（0–1）
   ├─ 证据链：字幕原句 ↔ 中文还原 ↔ 搜索摘要，逐条对齐
   ├─ 交付链接：抖音/百度搜索页 URL（稳定 GET；绝不给会话绑定链接，教训3）
   └─ 铁律不变：LLM 猜的剧名必须过存在性验证（cn_verify 三态 true/false/None 沿用）
```

## 四、质量门禁（上游，先于溯源）

| 门禁 | 做法 |
|---|---|
| 合集标志失真 | 重定义双信号：`duration>7200s` 或 标题正则（`EP\.?\s*\d+.*EP\.?\s*\d+` / `Full Movie` / 时长标注）；旧 flag 仅作弱参考 |
| 合集喂料 | is_compilation 条目 L2 只取**前 30 分钟**字幕对应字段（教训2：超长压缩+被动语态→主客体反转） |
| hook 范围 | opening_hook 只喂前 5 分钟（ingest 已切好 opening_0_3min） |
| evidence 强制 | 所有还原结论必须引用字幕原句，无原句=丢弃 |
| 放量纪律 | L1 全量跑（零网络）→ 抽样 30 条人工目视验收 L2/L3 质量 → 达标才开日增量 |

## 五、产出物

```
data/cn_drama_index.jsonl      # 片单索引：每周搜狗微信采集"短剧 片单/合集/资源 全集"文章 → 《剧名》+集数
data/drama_trace_v3/clusters.jsonl   # L1 姊妹簇全量（含繁中锚点命中标记）
data/drama_trace_v3/{video_id}.json  # 单条溯源：
  { video_id, fingerprint: {lines_cn[], names_cn[], details[]},
    candidates: [{cn_title, score, evidence: [{sub_quote, cn_restore, search_snippet}],
                  douyin_url, baidu_url, verified: true|false|null}],
    siblings: [video_id...], status: confirmed|top3|no_match }
data/drama_trace_v3/radar.json       # 搬运雷达聚合：中文母本 × 语种 × 中位播放 × 姊妹版数
```

面板：新增「搬运雷达」页（或并入蓝海雷达）——母本行展开多语种版本表现，空格子=语种蓝海机会。与图谱 v2.1 的「设定×母题×主线」共用配色和弹层交互。

## 六、实现顺序

1. **P0** L1 库内聚类脚本（纯本地，当天可验证）→ 出 clusters.jsonl + 人工抽查簇质量
2. **P0** 合集标志重定义 + 喂料门禁（改 ingest/analyze 侧，影响后续所有跑批）
3. **P1** 片单采集器 + cn_drama_index.jsonl
4. **P1** L2 指纹提取（bai prompt：直译还原，prompts.md 已有雏形）+ L3 搜索编排（复用 trace_v2 的 _baidu/_ddg/cn_verify，搜狗微信新写）
5. **P2** L4 打分 + 证据链输出 + 日报内嵌溯源小节（✅/❌/⚪）
6. **P2** 搬运雷达面板页；`data/drama_trace_v2/` 84 条旧输出归档删除
